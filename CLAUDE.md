# RPGMod — контекст проекта для Claude Code

RPG-мод для Terraria (tModLoader 1.4.4) с поддержкой Calamity: уровни, 6 статов, 4 класса, древо из 60 пассивных узлов, пробуждение. Отвечай пользователю по-русски.

## Источники правды

- `docs/DESIGN.md` — все механики, формулы, 60 узлов древа с ID и эффектами, пробуждение, архитектура, порядок этапов. Если код расходится с документом — прав документ; если документ кажется ошибочным — спроси, не исправляй молча.
- `docs/UI_SPEC.md` — утверждённый внешний вид (вариант A «ванильный инвентарь» + HUD). Макеты для справки: `docs/mockups/*.dc.html` (читать как текст, не запускать).
- `docs/ICONS.md`, `docs/icons.json` — список иконок и пути к файлам. Иконки делает Codex, не ты.

## Пользователь

Junior-разработчик (frontend + mobile: TypeScript, React, Go, Flutter). C# и tModLoader для него новые. Поэтому:
- объясняй решения коротко и по делу, при необходимости через аналогии с TS/React (например, `ModPlayer` ≈ состояние на игрока, `UIState` ≈ корневой компонент);
- делай изменения небольшими шагами, после каждого шага говори, что проверить в игре;
- не вываливай большие куски теории без запроса.

## Окружение и сборка

- tModLoader 1.4.4 (stable), C#, .NET 8. Внутреннее имя мода — `RPGMod` (если в `build.txt` / `.csproj` другое — используй то, что есть).
- Calamity — мягкая зависимость: в `build.txt` `weakReferences = CalamityMod`, без ссылки на его сборку. Доступ только через `ModLoader.TryGetMod("CalamityMod", out var calamity)`, `calamity.TryFind<ModNPC>(...)` и `calamity.Call(...)`. Имена NPC и ModCall-команд Calamity не угадывай — сверяйся с исходниками Calamity (github.com/CalamityTeam) или спроси пользователя.
- Сборка: попробуй `dotnet build` в папке мода. Если окружение этого не позволяет — попроси пользователя сделать Workshop → Develop Mods → Build + Reload и прислать ошибки.
- Запустить игру ты не можешь. Поэтому к каждому этапу добавляй короткий чек-лист ручной проверки.
- В `build.txt` должно быть: `buildIgnore = docs/*, tools/*, *.md, .git/*` (иначе документация и черновики иконок попадут в .tmod). Иконки в `Assets/` и `Content/` при этом должны паковаться.

## Правила кода

- API сверяй с ExampleMod для текущей версии tModLoader. Не используй устаревшее (`ModifyWeaponDamage` → `Player.GetDamage(DamageClass)` в `PostUpdateEquips` и т. п.).
- Узлы древа, уровни боссов, классовый прирост — **данные в реестрах** (`Common/Data/`), а не отдельный класс на узел. ID узлов строго из `docs/DESIGN.md`: от них зависят сохранения и имена файлов иконок.
- Все балансные числа — в `ModConfig` (`ConfigScope.ServerSide`), в коде только ссылки на конфиг.
- Сохранение через `TagCompound`. Загрузка устойчива к неизвестным/удалённым ID (пропускать, не падать).
- Мультиплеер с первого этапа: опыт начисляет сервер, пакеты через `ModPacket` с enum типов сообщений, синхронизация `SyncPlayer` / `CopyClientState` / `SendClientChanges`. Всегда проверяй `Main.netMode`.
- Весь текст для игрока — через локализацию (`Localization/ru-RU_Mods.RPGMod.hjson` + `en-US`).
- Отсутствующая текстура не должна ломать мод: `ModContent.HasAsset`, иначе заглушка (буква в слоте).
- Сделай отладочную `ModCommand` `/rpg` (level, xp, points, downed, reset), доступную только при включённом флаге отладки в конфиге — без неё тиры 2–3 и пробуждение не протестировать.
- PNG-файлы в `Assets/` и `Content/Items/*.png` не создавай и не меняй — это зона Codex.

## Процесс

1. Работай по этапам из раздела «Порядок разработки» в `docs/DESIGN.md` и чек-листам из `PROMPT_CLAUDE_CODE.md`.
2. Перед каждым этапом — короткий план (какие файлы и классы), жди «ок».
3. После этапа — сборка, отчёт что сделано, чек-лист проверки в игре, предложение коммита (`git`), если репозиторий есть.
4. Открытые вопросы из `docs/DESIGN.md` (раздел 8) не решай сам — спрашивай, когда до них дойдёт очередь.
